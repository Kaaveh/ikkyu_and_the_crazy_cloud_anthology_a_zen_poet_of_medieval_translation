## What this is

A Persian translation of **_Ikkyū and the Crazy Cloud Anthology: A Zen Poet of
Medieval Japan_** — Sonja Arntzen's translation of and commentary on the *Kyōunshū*
(狂雲集), the collected Chinese-language poems of Ikkyū Sōjun (1394–1481).

The infrastructure is finished and was built before any translation began
(`277d053`). What remains is the translation itself, plus the decisions it depends on.

## Structure

147 files under `fa/`, mirroring `source/` byte-for-byte:

| | |
|---|---|
| `plates.md`, `foreword.md`, `preface.md` | front matter |
| `introduction-1.md` – `introduction-4.md` | the translator's Introduction, four parts |
| `001.md` – `135.md` | the Anthology: 120 poems and 15 prose introductions |
| `abbreviations.md`, `notes.md`, `bibliography.md`, `index-of-poems.md`, `glossary-index.md` | back matter |

Files are numbered **by position, not by poem number**. Ikkyū's poem numbers are not
contiguous (6, 7, 8, 17, 25, …) and several level-3 blocks in the source are not
poems at all. `source/README.md` maps every file back to its heading; it is
generated by `split_book.py` and is excluded from translation via
`[tool.book] exclude` in `pyproject.toml`.

Part titles live in `_quarto.yml` as `part:` entries, so Quarto renders real part
title pages. Unlike Lin-chi, **no file here declares a parity offset for that** —
`split_book.py` does not put the part heading in the file.

`index.md` at the repo root is the website's home page. It is project chrome, not
translated content, and has no `source/` counterpart.

## Hard constraints

**The source text is not public domain.** Arntzen's translation is under copyright.
It is licensed to the maintainer for producing this translation and nothing else.
The monolith, the raw OCR, the PDF and `source/` are all gitignored and must stay
that way. This is why `check_parity` and `apparatus --check` report "skipped" when
run where `source/` is absent.

**`source/` is generated.** `split_book.py` produces it from the monolith, which
`generate_final_markdown.py` produces from the PDF. A defect in a source file is
fixed in one of those two scripts and re-split — never by editing `source/`, because
the next `just split` silently reverts it. See spec 002.

**`fa/` mirrors `source/` file-for-file.** Never concatenate. `check_parity` and
`apparatus --check` pair files by filename with a non-recursive scan; a merged or
renamed file silently disables both for that chapter.

**Runs are sequential.** gTranslator uses one Chrome profile
(`~/.gtranslate/chrome-profile`) and `_cleanup_chrome_profile()` SIGKILLs whatever
holds it at startup. Two concurrent runs means the second kills the first mid-file.
There is no parallelising the 147 files.

## The pipeline

Translation is done with **gTranslator**, at `~/Project/Backend/gTranslator`. It is
private, and nothing in `just check` depends on it — only producing a *new* draft
does.

```bash
GT=~/Project/Backend/gTranslator
.venv/bin/python tools/apparatus.py strip source/002.md -o /tmp/002.en.md
"$GT/.venv/bin/python" "$GT/gtranslate.py" \
    -f /tmp/002.en.md -t fa -w --raw -o /tmp/002.fa.md
.venv/bin/python tools/apparatus.py restore source/002.md /tmp/002.fa.md -o fa/002.md
```

**Two interpreters, and they are not interchangeable.** `tools/apparatus.py` needs
this repo's `.venv`, where `bargardan-tools` is installed; run it as
`tools/apparatus.py …` without the venv on `$PATH` and it dies with
`ModuleNotFoundError: No module named 'bargardan_tools'`. `gtranslate.py` needs
gTranslator's *own* `.venv`, where Playwright is installed. `CLAUDE.md` writes the
first one bare, which works only inside an activated venv — prefer the explicit form
above.

### `-w` is mandatory

Every other mode serves Google's **Classic** model, which translates clause by
clause and is markedly worse here. Only driving the real site reaches **Advanced**
(Gemini); no HTTP endpoint exposes it — not `translate_a/single`, not Cloud
Translation v2. Both were measured and both return Classic.

**The failure is silent.** Google downgrades any session whose User-Agent contains
`HeadlessChrome`, and while Classic is being served the model picker still reports
Advanced with `aria-checked="true"`. `gtranslate.py` overrides the UA in
`_open_context()` precisely to defeat this, and warns on stderr if the page ever
sees a headless UA again.

**Judge the output text, never the picker.** Advanced gives ezafe diacritics
(`چشمِ حقیقی`, `استادِ یی-وانگ`) and restructures sentences. Classic gives neither.
`fa/002.md` is the reference for what a good run looks like.

### `--raw` is mandatory, and matters more here than in the prose books

Without it, `clean_text()` unwraps hard line breaks before sending. On 135 files of
verse that runs a stanza together before the model ever sees it.

### Always through `tools/apparatus.py`

`strip` before, `restore -o` after. The adapter does exactly two things:

1. **Re-emits the structural heading labels** — `Poem N:`, `Notes`, `Plate N:`,
   `Prose Introduction to …` — from `source/`, so `شعر ۷` cannot become
   `قطعهٔ هفتم` three chapters later. The *title* after the label is real prose and
   is left for the translator.
2. **Puts back the hard line breaks** that hold a stanza together. The model strips
   the two trailing spaces, and without them every poem reflows into one paragraph.

It carries **no image or link machinery**, unlike Lin-chi's `anchors.py`. Measured
twice on a representative file: the Advanced model returns `#`/`##` markers and
`![alt](images/plate_1_calligraphy.png)` intact, path and all. This book also has no
inline note anchors — its endnotes are referenced by page number, not by a marker in
the text — so there is nothing inline to protect.

**Never `>` into `fa/`.** A redirect truncates the file before the tool can refuse a
bad draft. `restore -o` is the only thing that writes `fa/`, and it validates first.

### When `restore` refuses

It names the lines. `align_hard_breaks_by_block` aligns breaks run-by-run rather than
across the whole file, so it recovers on its own when the model re-breaks a poem
quoted inside a prose note — which it does, correctly, in `002.md`.

If it still refuses:

- **Edit the draft in `/tmp`, never `fa/`.**
- A hard-line-break refusal: end the named draft lines with two spaces, run again.
- A dropped-sentinel refusal: insert a bare `⟦n⟧` at the matching point in the
  Persian — the same clause, the same side of it. **Only ever insert or delete a
  bare `⟦n⟧`**; `restore` re-emits the label text from `source/`, so what you are
  choosing is a position and nothing else.
- **If most of a file's sentinels are missing, re-translate instead.** That is the
  silent `-w` failure above — Classic was served — and placing markers into a bad
  draft only makes it look finished.

Say in the commit body which markers were placed by hand. Nothing goes in the front
matter.

## Status values in `fa/`

Two states, not three. `untranslated` (what `make_stubs` writes) → `reviewed` (what
`restore` writes). **The machine draft is the edition**: there is no hand-revision
stage after the pipeline, so there is no later step to promote a `draft` into place.

`check_parity` and `apparatus --check` skip only `untranslated` and check everything
else.

Spec 001 made this true in the code: `DRAFT_STATUS` in `tools/apparatus.py` is
`"reviewed"`, and `CLAUDE.md` matches.

It also opened the only two exceptions to "`restore` is the only thing that
writes `fa/`" — the obscene-poem marker and conforming a proper noun to
`STYLE.md` §2, both hand-edits made after `restore`. `CLAUDE.md` names them.

## Toolchain

```
just check     # everything that must pass before a commit
just fix       # the corrections that can be made automatically
just stubs     # create or refresh fa/ from source/ — never overwrites work
just split     # rebuild source/ from the monolith. Destructive.
just build     # HTML, PDF and EPUB
just serve     # live preview on :4200
just venv      # set the host Python environment up
```

## What the checkers catch

The checkers are the **`bargardan-tools`** package, shared with the other books in
this corpus and installed from `tools/requirements.txt`, pinned to a tag. There is no
vendored copy here. It reads its config relative to the *current directory*, so
running it from the repo root picks up this project's `pyproject.toml`. Nothing in it
knows which book it is checking.

| Check | Catches |
|---|---|
| `normalize` | Arabic Yeh/Kaf, ZWNJ discipline, Arabic-Indic digits, Tatweel, quotes, **bidi overrides** (reported, never auto-fixed) |
| `check_parity` | a dropped paragraph, by block count against `source/` |
| `apparatus --check` | lost hard line breaks (verse reflowed into prose), lost anchors |
| `tools/tests` | the adapter itself |

Three things to know about them:

- **`check_linebreaks` is deliberately absent from `just check`.** It enforces one
  sentence per line, which is right for prose and meaningless for verse, and this
  book is mostly verse. The note is at the foot of `pyproject.toml`.
- **Bidi overrides are reported but never auto-fixed**, so `just fix` can leave
  `just check` failing. That is by design — a human has to look at those.
- **`normalize`'s `quotes` rule is script-blind.** It rewrites ASCII and curly quotes
  to `«»` anywhere, including inside verbatim English. Spec 006 needs
  `<!-- normalize: off -->` regions because of this.

## There is no glossary checker

`bargardan-tools v0.1.0` ships `anchors`, `check_linebreaks`, `check_parity`,
`make_stubs` and `normalize`. Lin-chi's `check_glossary` / `glossary.yml` mechanism
**does not exist here**, and no spec should assume a gate that will never run.

Terminology consistency in this book is a human discipline. Spec 001 records the
recurring renderings in `STYLE.md` and says plainly that nothing enforces them. The
one thing that *is* enforced mechanically is the structural heading labels, by
`apparatus.py` — which is why the book cannot drift on `شعر N:` even though it can
drift on everything else.

## Register, in one paragraph

The book is three books in one, and this is the thing most likely to go wrong.
Arntzen's Introduction is modern scholarly English with dates, citations and
institutional history. The poems are four-line Chinese quatrains rendered compactly
and formally. And a large part of the Anthology is blunt, erotic and satirical —
brothels, Lady Mori, monks shamed by name — in the same compact form. A single
register flattens all three: scholarly Persian throughout makes the erotic poems
prim, and a loosened register makes the Introduction sound careless. `STYLE.md` §1 is
where this gets decided; spec 001 is where it gets done.

## Publication

Quarto book project, three formats. PDF is **LuaLaTeX**, not XeLaTeX — under
XeLaTeX pandoc picks babel with `bidi=default`, which reverses Latin-script runs
embedded in Persian, and this book's notes are full of them. The reasoning is in
`tex/preamble.tex`. Spec 007 covers the first release.

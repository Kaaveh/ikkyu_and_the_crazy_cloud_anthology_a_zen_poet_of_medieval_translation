# 002 — Source Repair

**All 147 files in `source/`, audited against the 228-page PDF.**

## Context

`source/` is three transformations away from the book: PDF → `…raw.md` (OCR) →
`…translation.md` (`generate_final_markdown.py`, 960 lines of typo dictionary and
structural reassembly) → `source/` (`split_book.py`). Each step is lossy, and the
damage that survives all three is damage a translator will faithfully carry into
Persian.

Four defects were found by inspection before any audit, which is the reason this spec
exists at all. They are listed below with their evidence. The audit is not a search
for *these* — it is a read of all 147 files, of which these are the known starting
points.

**Why before translating, and not after:** a damaged file wastes a translator run,
and the run is the expensive part. Worse, a Persian file produced from damaged
English *looks finished*. Nothing in `just check` can tell that `fa/032.md` is filed
under the wrong poem — parity compares block counts, and the block counts match.

## Goal

Every file in `source/` read against the PDF, every defect fixed in
`generate_final_markdown.py` or `split_book.py`, `just split` reproducing a clean
147-file tree.

## Dependencies

None.

## Requirements

1. **Fix the generator, never the files.** `source/` is regenerated by `just split`
   and an edit to a file there is reverted by the next run, silently. Every fix lands
   in `generate_final_markdown.py` (for OCR and structure) or `split_book.py` (for the
   split itself), and is verified by re-running `just split` and re-reading the
   output.

2. **`source/032.md` is filed under the wrong poem.** Its heading is a byte-for-byte
   duplicate of `source/003.md`'s:

   ```
   # Poem 8: On the Topic of The Venerable Master Daitō’s Conduct
   ```

   Its body is a different poem — *"Crazy Cloud, who knows to what wild wind he
   belongs?"*. The raw OCR shows what it actually is:

   ```
   …raw.md:4802    8
   …raw.md:4803    From the Mountains, Returning to the City      自 山中
   …raw.md:4804                                                   帰 市中
   …raw.md:4824    101   POEM NUMBER     93
   ```

   That bare `8` is page furniture and `generate_final_markdown.py:587` read it as
   the poem number. The real number is twenty lines later, in the page footer, and
   `POEM_TITLES` already holds the correct entry at line 365:

   ```python
   '93': 'From the Mountains, Returning to the City',
   ```

   So the fix is in `get_num()` / the number detection at line ~586, not in the title
   table. **This is the single most important item in this spec**: a wrong poem title
   is a wrong chapter forever, and it is the one defect no checker can catch.

   It is also the only one of its kind. Poem numbers run monotonically through the
   book; this is the one inversion. The scan is one command and belongs in the
   acceptance criteria:

   ```bash
   for f in source/[0-9]*.md; do
     head -1 "$f" | sed -n 's/^# Poem \([0-9]*\):.*/\1/p'
   done | awk 'NR>1 && $1+0 < prev {print "NON-MONOTONIC at", NR, $1, "after", prev} {prev=$1+0}'
   ```

3. **`source/notes.md` has marginal letters interleaved into every note.** 17.5 K
   characters, and the damage is systematic — a narrow column of stray characters
   from the facing page has been merged into the text line by line:

   ```
   1. For a detailed treatment of the Onin i War in English, see Paul Varley,
   The Onin N War. For an overview of the Muromachi t period, see George Samson,
   A History ofJa- c pan 1334-1651, and J.W. Hall and Toyoda w Takeshi, eds.,
   Japan in the Muromachi Era. c
   ```

   Unusable as translator input as it stands: the model will render `ofJa- c pan` as
   something, and whatever it renders will be wrong. This is the largest single
   repair in the spec and the one most likely to need a targeted pass in
   `generate_final_markdown.py` rather than entries in the typo dictionary.

   `notes.md` has two sections — `## Notes to Introduction` (88 notes) and
   `## Notes to Translations` (116). Both are affected.

4. **Untranscribed CJK column text bleeds into English verse lines.** The print
   edition sets the Chinese original in a right-hand column; where the OCR failed to
   read it as CJK it transcribed it as Latin gibberish and the reassembly appended it
   to the English line. Scanned: **14 files, 39 lines**. Examples:

   ```
   source/029.md   Ten years spent in brothels, elation difficult to exhaust. TEL ek RE 9S
   source/048.md   In the midst of pleasure there is pain in Ikkyi’s school. SE BAR Te — KPA
   source/048.md   Each frog fighting for respect at the bottom of the well; fei ~ HEEStHf EKBS
   ```

   The scan that found them:

   ```bash
   .venv/bin/python - <<'EOF'
   import re, pathlib
   OK = {"I","A","CZS","KZ","SP","T","ZZ","II","III","IV","V","VI","VII","VIII","IX","X","AD","BC"}
   pat = re.compile(r"\b[A-Z][A-Za-z]*[A-Z][A-Za-z0-9]*\b")
   for p in sorted(pathlib.Path("source").glob("*.md")):
       if p.name == "README.md": continue
       for i, line in enumerate(p.read_text(encoding="utf-8").split("\n"), 1):
           if len([t for t in pat.findall(line) if t not in OK]) >= 2:
               print(f"{p.name}:{i}: {line[:100]}")
   EOF
   ```

   It is a heuristic, not a proof — it will miss lowercase gibberish and flag the
   occasional legitimate line. Use it to find candidates, not to declare the file
   clean.

5. **Four files do not open with their level-1 heading.** `005.md`, `029.md`,
   `048.md` and `076.md` each begin with a bold set-header line above the heading:

   ```
   **Hsii-t’ang’s Three Pivot Phrases**

   # Poem 25: One’s Eyes Are Not Yet Clear; …
   ```

   `apparatus.py`'s `token_re()` documents "Every file in `source/` opens with its
   level-1 heading; `split_book.py` normalises the levels so that is always true" as
   an invariant. It is false. It does not currently bite, because the invariant is
   only relied on for files listed in `[tool.book.titles]` and these four are not —
   but a stray bold paragraph also floats above the chapter title in the rendered
   book.

   Decide in this spec whether the set header becomes part of the heading, a separate
   level-2 heading, or is dropped, and fix `split_book.py` accordingly. Note that
   `029.md` and `076.md` carry OCR damage *in the set header itself*
   (`**Living in the Mountains            two poems**`,
   `**Picture of an Arhat Reveling in a Brothel: two      poems**`).

6. **The subject's own name is misspelled throughout.** Counted across `source/`:

   | form | occurrences |
   |---|---:|
   | `Ikkyū` (correct) | 218 |
   | `Ikkyu` (macron lost) | 147 |
   | `Ikkyi` | 56 |
   | `Ikkyai`, `Ikkyas`, `Ikkyus`, `Ikkyti`, `Ikkyta`, `Ikkyit`, `Ikkyaii` | 9 |

   The typo dictionary at `generate_final_markdown.py:9` already maps ten variants
   including `Ikkyii` — but not `Ikkyi`, and it does not touch the bare `Ikkyu`,
   which is 147 of the 212 wrong ones. Both are one entry each.

   Do the same count for the other recurring names the dictionary already tracks
   (`Sōjun`, `Kyōunshū`, `Yōsō`, `Daitō`, `Kasō`, `fūryū`) before declaring it done;
   the same "correct form plus a long tail" shape is likely.

   ```bash
   grep -roh 'Ikky[a-z]*' source/*.md | sort | uniq -c | sort -rn
   ```

   This one matters beyond tidiness: the Persian transliteration is generated from
   whatever the English says, so `Ikkyi` becomes a different Persian name than
   `Ikkyū` does, in the middle of a book about him.

7. **Also check, because the audit is a read anyway:**
   - Endnote digits fused to the preceding word (`(See poem no 287.)3`,
     `Onin War.1`), throughout the Introduction.
   - Words run together (`ofhistorians`, `susuperiors`) and stray CJK punctuation
     (`、`) in `introduction-1.md`.
   - `bibliography.md` and `glossary-index.md` are half-garbled CJK. **These are
     lower priority**: spec 006 keeps their entries verbatim, so bad OCR there is
     visible to the reader as bad OCR rather than laundered into confident Persian.
     Fix what is cheap; do not hold the spec on them.

8. **Do not "improve" the English.** The job is to recover what the page says, not
   to edit Arntzen. Where the OCR is ambiguous and the PDF is unreadable, leave it and
   note it.

## Acceptance criteria

- [ ] `just split` reports `Wrote 147 files to source/` and the tree is byte-stable
      across two consecutive runs.
- [ ] No two files in `source/` share a level-1 heading.
- [ ] The monotonic-poem-number scan in requirement 2 prints nothing.
- [ ] `source/032.md` is headed `# Poem 93: From the Mountains, Returning to the City`.
- [ ] `source/notes.md` reads as English prose end to end.
- [ ] `grep -roh 'Ikky[a-z]*' source/*.md | sort -u` returns nothing — every
      occurrence is `Ikkyū`.
- [ ] The gibberish scan in requirement 4 returns only lines a human has looked at
      and accepted.
- [ ] Every file in `source/` opens with a level-1 heading, or the four exceptions
      are a recorded decision rather than an oversight.
- [ ] `just check` passes.
